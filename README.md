# ScscriptriPt Blog

使用 MkDocs Material 建站的个人web，不仅限于blog。

San 值在这个时代是稀缺品，而我恰好没有，以下是网站结构简介（给人看）：

- `Blog` ：记录个人对于科技、人际关系、社会等的思考，可能也有个人经历，如果痛击了我生活中真实的朋友们，我很抱歉😂，无论是美好的还是悲伤的
- `AGI时代`：AI-Agent知识、科技要闻、厂商/模型的意外事故
- `安全时代`、`计算机时代`：专业材料与知识点，计算机时代还放了部分资源，非专业人士阅读后果自负
- `缺德时代` ：个人的各种疯狂言论和发癫过程，San值严重匮乏。这甚至会引人不适，专业人士阅读也后果自负
- `安全资源集合`：记录各种个人用过或者没用过的平台，网络安全相关资源，适合随便乱逛点击两下看看


# 维护要求

Agent 总是不受控地糟蹋项目。网站搭建初期，大部分工作都由Agent代劳完成。

个人web和代码产品不同，代码可以要求跑通就行，但个人web重要的是文档內容不是代码。

由 Agent 生成的文本总是带有浓烈的「 AI臭味」，文档给人看，不是给Agent看的，所以 Agent 不应当擅自更改文档表述类內容。同时 Agent 也会自作聪明做文档分类，但这分类要求并不是作者想要的。

和「 AI Slop」斗争这件事让人非常头疼，Agent修改本文档时只能修改结构更新，但不能随意修改说明文字，否则人工复核浪费时间与精力

## 01-结构限制

### 01-单Tab嵌套目录限制

受 material 框架限制，导航结构最多只能嵌套三层，多层嵌套会导致渲染出错

```text
Tab
└─ 一级集合（文件夹 + index.md）
   └─ 二级文件（.md）
```

结构说明：

- 一级集合容纳多篇内容，一般为文件夹，但material的结构稍有不同，一级集合的本身也可以写入一部分內容，在index.md内
- 二级文件必须是 `.md` ，再嵌套就会渲染出错。分类不够只能升级为一级集合，或新开 tab
- 图片集中在 `docs/assets/`，按来源保留目录，不散在文章目录

Tab 顺序固定如下，如果后续增加了新 Tab 在没有人为特别指定下，默认添加在「 安全资源集合」前，「 安全资源集合」默认为 The Last Tab

```text
 About Me | Blog | AGI时代 | 缺德时代 | 安全时代 | 计算机时代 | 安全资源集合
```

### 02-资源定位约定

| Tab          | 源文件目录                                                   |
| ------------ | ------------------------------------------------------------ |
| Blog         | `docs/blog/posts/`                                           |
| 关于         | `docs/About-Me.md`                                           |
| 安全时代     | `docs/安全时代/`                                             |
| 计算机时代   | `docs/计算机时代/`                                           |
| AGI时代      | `docs/AGI时代/`                                              |
| 缺德时代     | `docs/缺德时代/`，警告页为 `docs/缺德时代/正文前介绍和警告.md` |
| 安全资源集合 | `docs/安全资源集合/`                                         |

### 03-图片资源

图片根目录固定为：

```text
docs/assets/
├─ avatar.jpg
├─ AGI时代/
│  ├─ 未来已来/
│  ├─ 未来别来！/
│  └─ 原来是劣等模型/
└─ 明日方舟/
   └─ <活动名>/
```

- 新图片先按所属栏目放进 `docs/assets/` 对应子目录，再在 Markdown 中引用。
- 明日方舟图片保留活动层级，避免 `event-cover.png` 等同名文件互相覆盖。
- Markdown 中使用相对路径，例如活动章节引用 `../../assets/明日方舟/<活动名>/图片.png`。

## 03-MkDocs 实施要求

- `mkdocs.yml` 的 `nav` 按以下顺序排列：`About-Me | Blog | AGI时代 | 缺德时代 | 计算机时代 | 安全时代 | 安全资源集合`。
- `navigation.indexes` 已经开启，每个一级集合都需要 `index.md`。
- 博客分类使用 blog 插件管理，不手工创建深层分类目录。
- 每个一级集合是一个文件夹；文件夹内直接放章节或文章 `.md` 文件。
- 不使用三级目录组织内容；更深的内容用页面内 H2/H3。
- 所有梗图和荒诞项目最好都有对应的 Markdown 页面，写明来源、时间、背景和标签。
- 使用标签做跨栏目聚合，例如 `地狱笑话`、`脑袋落地`、`Agent`、`模型事故`、`AI神鬼操作`。
- 不创建长期为空的目录，先写内容，再补导航。：
