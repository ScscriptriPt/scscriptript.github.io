# ScscriptriPt Blog

个人网站，使用 MkDocs Material 搭建。

## 站点定位

**一个低 SAN 的个人终端。**

- `Blog` 负责认真输出；
- `安全时代`、`计算机时代`、`AGI时代` 负责长期积累；
- `缺德时代` 负责系统异常日志。

一句话版本：

> 理智欠费，仍在输出。

更完整一点的版本：

> 认真记录技术，也认真记录人类拿技术做出来的怪东西。

## 导航规则

导航最多三层：

```text
Tab
└─ 一级集合（文件夹 + index.md）
   └─ 二级文件（单篇 Markdown）
```

约束：

- 一级栏目是能容纳多篇内容的集合，通常是一个文件夹。
- 二级节点只能是单篇 `.md` 文件，不再继续分目录。
- 如果内容还需要分类，就把它提升为一级栏目，或者拆成新的 Tab。
- 更深的内容使用页面内的 H2/H3，不再增加导航层级。
- 技术栏目保持可检索；个性化主要放在副标题、栏目说明和内容语气里。
- 所有图片统一放在 `docs/assets/`，按内容来源保留子目录，不把图片散落在文章目录里。

一级导航顺序固定为：

```text
Blog | 关于 | 安全时代 | 计算机时代 | AGI时代 | 缺德时代 | 资源集合
```

`Blog` 放在第一位，因为这是个人网站，不是纯知识库。首页不再做四卡入口；Blog 作为站点入口，或者只保留一段个人介绍。

## 各分区规则

### Blog

博客文章放在 `docs/blog/posts/`，分类使用 Material blog 插件的 frontmatter 控制，不再手工创建深层分类目录。

| 分类 | 放什么 |
|---|---|
| 反过来走走 | 社会、教育、就业、人际、政策和现实生活观察 |
| 无法抵达的潮流 | 开发、工具、AI 和安全学习中的技术记录 |
| 同一次跌倒 | 项目复盘、翻车记录、事后分析 |
| 大地巡礼 | 个人感想、情绪、生活体验和零散思考 |
| 赛博破烂 | 课程、书、工具、资料和阅读笔记 |
| 网安哲思 | 安全行业的思考、方法与反思 |
| 计算机哲思 | 计算机、软件与工程的思考 |

博客只放愿意作为个人代表作的高质量文章。更细的主题使用标签，例如 `内卷`、`边界感`、`就业`、`Agent`、`开源`。

### 安全时代

安全时代是主方向，包含安全基础、Web、网络协议、渗透、红队、代码审计、逆向、漏洞利用、免杀、应急、取证、云原生和安全开发。

每个一级栏目是一个集合，目录内至少包含：

```text
docs/安全时代/Web安全/
├─ index.md
├─ 01-HTTP与Web基础.md
├─ 02-SQL注入.md
└─ 03-XSS.md
```

一级栏目：

| 栏目 | 内容 |
|---|---|
| 安全基础 | 安全模型、威胁建模、认证授权、密码学基础 |
| Web安全 | HTTP、SQL注入、XSS、SSRF、文件上传、反序列化 |
| 网络与协议安全 | TCP/IP、DNS、TLS、流量分析、中间人 |
| 渗透测试 | 信息收集、边界突破、权限提升、横向移动、报告 |
| 红队与内网 | AD、Kerberos、域渗透、C2、权限维持 |
| 代码审计 | PHP、Java、Python 审计，危险函数与漏洞模式 |
| 二进制与逆向 | 汇编、调试、静态分析、漏洞定位 |
| 漏洞分析与EXP | 漏洞复现、PoC、EXP 开发、利用链 |
| 免杀与加壳 | Shellcode、加载器、混淆、加壳、EDR 对抗 |
| 应急响应 | 入侵排查、日志分析、恶意样本、处置 |
| 数字取证 | 磁盘、内存、网络取证、证据链 |
| 云原生与容器安全 | Docker、Kubernetes、云 IAM、供应链 |
| 安全开发与DevSecOps | SDL、SAST/DAST、依赖安全、CI/CD 安全 |
| 安全工具与靶场 | Burp、Nmap、Metasploit、HTB、靶场笔记 |

如果某个方向继续膨胀，增加一级栏目或拆分独立 Tab，不增加第三层目录。

### 计算机时代

计算机时代负责计算机基础与软件工程，不包含网络安全。

`C语言`、`Python`、`操作系统` 等本身就是一级栏目。正确层级是：

```text

```

```text
计算机时代 → 软件工程 → 编程语言 → C语言 → 01语法.md
```

### 缺德时代

缺德时代是独立的低 SAN 输出区，不放进 Blog。

`正文前介绍和警告` 是进入分区前的独立页面，不属于任何集合。一级栏目如下：

| 栏目 | 内容 |
|---|---|
| 正文前介绍和警告 | 进入分区前的提示、免责声明和内容警告；单独一页 |
| 地狱笑话 | 黑色幽默、低 SAN 短文和抽象段子 |
| 脑袋落地 | 对政策和公共事件的讽刺、吐槽和评论 |
| 智商下线 | 对平台、产品、厂商和现实行为的刻薄观察 |
| 赛博民俗 | 互联网亚文化、网络怪谈、梗的传播和二次创作 |
| 梗图收容 | 不属于具体 AGI 事件的梗图和图片短评 |

梗图不单独做 Tab，也不单独做顶层栏目。模型相关梗图按内容归入 AGI时代：

- 模型发布、能力变化、行业里程碑 → `AGI时代 / 未来已来`
- 荒诞 AI 项目、用户拿强模型做怪事 → `AGI时代 / 未来别来！`
- 模型自己犯蠢、官方运营翻车 → `AGI时代 / 原来是劣等模型`

## 固定命名与边界

### 缺德时代命名

分区名固定为 `缺德时代`。

副标题：

> 理智欠费，精神状态不详。

备选名称：`理智欠费`、`不可回收`、`赛博地府`、`缺德电台`。

### 未来已来

定位：**已经发生的科幻**。

记录已经发生、并且改变了默认值的事件。不是每个模型发版都收录，只有能力、成本、工作流、风险或规则发生实质变化时才收录。

典型内容：

- 模型能力和价格出现跨代变化；
- Agent 能完成以前只有人才能完成的事情；
- MCP、工具调用等生态标准发生变化；
- 服务器中断、补偿、限流等基础设施事件；
- AI 进入安全、教育、内容生产等领域的历史节点。

### 未来别来！

定位：**拒收这份未来**。

副标题：

> 这么强的技术，你拿来做这个？

这里不是 AI 威胁论，也不是单纯的经济焦虑，而是收集 AI 用户做出来的荒诞项目、神鬼操作和技术过剩现场。

典型内容：

- 把平台风控做成躲猫猫游戏；
- 果蝇桌宠把桌面当成繁殖地；
- Agent 清理内存时顺手杀掉杀毒软件，然后自己被反杀；
- 用最强模型做完全没有必要的东西；
- 技术上成立、但精神和审美上让人拒绝签收的项目；
- 已经出现、但让人产生“我不想住在这个未来”的现实切片。

可用标签划分子系列，不增加目录层级：

- `诡异项目`
- `AI神鬼操作`
- `技术过剩现场`
- `赛博民俗`
- `我不想住在这个未来`

每篇内容可以采用“未来拒收档案”的形式：

```text
档案编号：FUT-2026-001
项目名称：
它做了什么：
技术含量：
荒诞点：
我的精神状态：
是否愿意住在这个未来：
```

### 原来是劣等模型

名称固定为 `原来是劣等模型`

它主要收录：

- 模型自己的尴尬时刻；
- 官方运营和厂商行为的翻车；
- 模型能力、价格、策略上的反差；
- 用户对厂商操作的嘲笑和记录。

和 `未来别来！` 的区别：

- 笑点是“模型怎么这么蠢 / 厂商怎么这么抽象” → `原来是劣等模型`
- 笑点是“模型明明能干活，用户却拿它做这个” → `未来别来！`

### 厂商行为艺术

用于收录厂商政策、封号、地区限制、条款变化、价格调整、公关翻车等事件。

## MkDocs 实施要求

- `mkdocs.yml` 的 `nav` 按以下顺序排列：`Blog | 关于 | 安全时代 | 计算机时代 | AGI时代 | 缺德时代 | 资源集合`。
- `navigation.indexes` 已经开启，每个一级集合都需要 `index.md`。
- 博客分类使用 blog 插件管理，不手工创建深层分类目录。
- 每个一级集合是一个文件夹；文件夹内直接放章节或文章 `.md` 文件。
- 不使用三级目录组织内容；更深的内容用页面内 H2/H3。
- 所有梗图和荒诞项目最好都有对应的 Markdown 页面，写明来源、时间、背景和标签。
- 使用标签做跨栏目聚合，例如 `地狱笑话`、`脑袋落地`、`Agent`、`模型事故`、`AI神鬼操作`。
- 不创建长期为空的目录，先写内容，再补导航。

`缺德时代` 的导航应显式写成这样，警告页必须排在第一个子项：

```yaml
nav:
  - 缺德时代:
      - 正文前介绍和警告: 缺德时代/正文前介绍和警告.md
      - 地狱笑话:
          - 缺德时代/地狱笑话/index.md
          - 哦耶: 缺德时代/地狱笑话/哦耶.md
      - 脑袋落地:
          - 缺德时代/脑袋落地/index.md
      - 智商下线:
          - 缺德时代/智商下线/index.md
      - 赛博民俗:
          - 缺德时代/赛博民俗/index.md
      - 梗图收容:
          - 缺德时代/梗图收容/index.md
```

注意：`navigation.indexes` 只负责把集合目录里的 `index.md` 变成可点击的分区入口，不会自动把未写进 `nav` 的章节文件挂上去。当前项目使用手写 `nav` 时，二级文件需要显式列出；如果以后不想维护长导航，再考虑自动导航插件。
