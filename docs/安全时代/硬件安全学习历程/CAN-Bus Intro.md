CAN Bus 的优势：
- 简单且低成本：没有复杂的图形网状结构，减少复杂性，布线
- 简单的访问
- 极度耐操：对电磁干扰等强抵抗，安全性就很好了
- 高效，CAN frame 按照 ID 从优先级排序，高优先级率先总问，不会导致其他帧中断和错误


从经典 CAN 转向 CAN-FD 和 CAN XL 的进程是非常缓慢的

如果从网络层次的角度上看待 CAN，它是数据链路层和物理层的集合体

- 链路层：规定 CAN 帧格式，错误处理、仲裁
- 物理层：定义电缆类型，电平、节点要求、电缆阻抗，波特率，靛蓝长度，终端

CAN帧：
- SOF
- ID
- RTR：指示发送还是请求数据
- 控制域
- Data

- EOF

如何记录 CAN 总线数据？

1. 选择合适硬件
2. 确定适配线缆
3. 配置并连接设备
4. 查看原始 CAN 数据

选择硬件：

先确定数据采集方式：can 转 usb、can 转 sd 、can 转云端？

然后适配器：OBD2、J1939、M12、非接触式

配置并连接设备：先考虑波特率和请求，设备波特率和CAN总线必须匹配，如果需要记录 OBD2/UDS等按需数据，必须配置设备域传输相关的“传输消息”

如何解析 MF4 文件，而不仅仅看着一大串字节序列阅读？需要使用 DBC 文件进行解码，

CAN DBC：CAN 数据库文件是一种文本文件，包含了解码原始 CAN 数据的信息

一般来说，DBC 文件由原始设备制造商提供（OEM），获取 DBC 文件的方法：

1. 查看文件
2. 找 OEM 要
3. 使用标准 DBC，而非厂商的专用 DBC
4. 逆向工程
5. 外部化：使用传感器到 CAN 模块来填补专有空白
